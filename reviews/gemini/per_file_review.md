## Makefile

### **Makefile Review: mandelbrot_fortran**

The `Makefile` is functional for simple serial builds but contains structural flaws that will cause failures in parallel execution and lacks portability for cross-platform development.

---

#### **Bugs & Correctness**

*   **[P1] Missing Fortran Module Dependencies (Lines 27-28):**
    Fortran modules create a strict compilation order requirement. `src/mandelbrot.f90` depends on `mod_cli` and `mod_ppm_writer`. Without explicit dependency rules, a parallel build (`make -j`) will fail because it will attempt to compile `mandelbrot.f90` before the required `.mod` files are generated by the other source files.
    *   *Fix:* Add `$(BUILD_DIR)/mandelbrot.o: $(BUILD_DIR)/cli.o $(BUILD_DIR)/ppm_writer.o`.

*   **[P1] Risky Target Dependency on Directory (Line 24):**
    The `$(TARGET)` depends on `$(BUILD_DIR)`. On many filesystems, a directory's modification time is updated whenever a file within it is created or renamed. This causes the executable to be unnecessarily relinked every time any object file is updated.
    *   *Fix:* Use an order-only prerequisite for the build directory: `$(OBJECTS): | $(BUILD_DIR)`.

---

#### **Maintainability & Portability**

*   **[P2] Docker UID/GID Portability Hazard (Line 45):**
    The shell expansion `$$(id -u):$$(id -g)` is Linux-specific. This will cause failures or unexpected behavior on macOS or Windows (Docker Desktop), where volume permission mapping is handled differently or the `id` command is not available in the same context.

*   **[P2] Redundant Variable (Line 17):**
    `MODULES = $(BUILD_DIR)/*.mod` is defined but never used in any recipe. While `clean` removes the whole directory, keeping dead variables reduces clarity.

*   **[P3] Incomplete Preflight Checks (Lines 21-22):**
    The `preflight` target only verifies `gfortran`. However, the `png` target relies on `magick` (ImageMagick v7), and the `docker-*` targets rely on `docker`. Users attempting these targets will receive generic shell errors rather than the helpful guidance provided for the compiler.

### [P0] Critical Logic & Functional Bugs

*   **Line 1168: Impossible Assignment Completion.**
    `required_pct = max(100.0, target_value)` 
    If a user sets a target of 80%, this logic forces it to 100%. If they set it to 100%, it remains 100%. This effectively makes any `quiz_score_pct` assignment impossible to complete unless the user achieves a perfect score, regardless of the intended `target_value`.
*   **Line 1253-1261: Brittle Streak Calculation.**
    The `daily_goal_status` loop breaks immediately if `today` is missing an entry. If a user has a 10-day streak but hasn't completed *today's* goal yet, `today_count` is 0 and the function returns a streak of 0. Streaks are typically reported as "current up to yesterday" until the daily goal is met.
*   **Line 1300: Non-deterministic Fallback in `_iso_day_utc`.**
    If a date string fails to parse, it returns `datetime.now().date()`. In a database context, this can lead to "split-brain" data where records are bucketed into different days based on the exact millisecond of a system clock failure or parsing error, rather than failing loudly or using a stable null value.

*   **Line 34: Missing Concurrency Handling.**
    `sqlite3.connect(cfg.path)` is called without a `timeout` parameter or explicit WAL mode activation. In a UI-driven application, concurrent writes (e.g., saving a quiz result while the background learning engine updates progress) will frequently trigger `sqlite3.OperationalError: database is locked`.

For `subskill_mastered` targets (Line 1170), it checks mastery for the subskill but does *not* verify if the current `attempt_id` actually contributed to that subskill.
