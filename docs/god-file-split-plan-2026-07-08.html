AGENTS target: keep modules near ≤300 LOC; propose a split before large edits.

Goals

  • Stable public APIs: from app import db, generate_question, ParentPanel, QuizPanel
  • No schema, pedagogy, or UI redesign in split PRs
  • PR stack with tests after each step
  • Non-goal: sync product completion, content rewrites, packaging redesign

UI: keep public classes; compose per-tab/section modules.

PR sequence

  1. PR0 — This plan + baseline tests
  2. PR1 — db package + facade + shared config provider + explicit __all__ (highest value)
  3. PR2 — quiz_engine types/choices/dispatch/skill bodies
  4. PR3 — ParentPanel composition by tab
  5. PR4 — QuizPanel session/view/historical split
  6. PR5 — Optional summer_program / docs cleanup

First implementation slice when approved: PR1 only, then stop and reassess.

Verification (each PR)

  • python -m compileall app
  • Import smoke for db, quiz_engine, UI panels
  • Focused unit tests for touched surface
  • python -m unittest discover -s tests -q
  • Line-count report; document any >300 pure-DDL exception

Risks

  • Circular imports in db package → one-way dependency on connection
  • PyInstaller hiddenimports after package rename → packaging smoke
  • Silent behavior drift in generation/PIN/assignments → move-only PRs + existing tests
  • Tk lifecycle bugs → one parent tab per change set
